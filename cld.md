Задача запущена и работает. **Можешь закрыть ноутбук прямо сейчас** минуты на 3–4.

**Как увидишь результат, когда вернёшься.** Открой в VS Code файл [laptop-test.log](laptop-test.log) или выполни в терминале `cat ~/laptop-test.log`. Там будет 12 строк с отметками времени, примерно 11:16–11:19 UTC, и в конце строка «ГОТОВО». Подсказка: в столбце «SSH-сессий» на время, пока ноутбук был закрыт, число станет меньше. Как сделать так, чтобы я работал без VS Code: запускать меня в tmux. tmux — это «вечный терминал» на сервере. Он живёт независимо от твоего подключения.

В терминале VS Code (или по обычному ssh): tmux new -s claude
Внутри набираешь claude и даёшь задачу.
Закрываешь VS Code или ноутбук, я продолжаю работать.
Когда вернёшься, подключаешься и набираешь tmux attach -t claude: увидишь всё, что я сделал за это время.

Теперь про твой вывод, тут важно не перепутать: это зависит от того, где ты пишешь.

Где пишешь задачу	Закрыл VS Code — что будет
В этой панели чата VS Code (как сейчас)	Работа остановится. Эта панель привязана к окну VS Code.
В терминале после команды cc	Работа продолжится. Claude живёт в tmux на сервере, и VS Code ему не нужен.
Оба варианта — один и тот же Claude с теми же знаниями о тебе (он прочитает CLAUDE.md). Отличается только «окно», через которое ты с ним говоришь. Это два отдельных разговора: то, что ты обсуждал в панели, сессия в cc не увидит, и наоборот.

Как пользоваться:

В VS Code открой терминал: Ctrl+`` (или меню Terminal → New Terminal).
Набери cc, откроется Claude в папке projects.
Дай задачу и смело закрывай VS Code или ноутбук.
Когда вернёшься, открой терминал и снова набери cc. Подключишься к той же сессии и увидишь всё, что было сделано.
Если нужно выйти из tmux, но Claude не останавливать: Ctrl+B, отпустить, затем D.
Практический совет: короткие вопросы и обсуждения удобнее вести в панели, а всё, что займёт больше нескольких минут или должно идти без тебя, запускай через cc.

Одна мелочь: в Linux cc — ещё и стандартное имя компилятора C. Сейчас его на сервере нет, а моя команда влияет только на то, что ты набираешь руками в терминале, сборку программ она не ломает. Если захочешь другое имя, переименую за секунду.

## Памятка

**Что теперь умеет сервер**
- **Безопасность:** вход только по ключу, пароли отключены. Firewall ufw пропускает только SSH, сайты (80/443) и VPN (56117, 2058, 41846). fail2ban блокирует подбор паролей. Обновления безопасности ставятся автоматически.
- **Рабочая папка:** `/home/claude/projects`. В ней лежит [CLAUDE.md](projects/CLAUDE.md) с информацией о тебе, и я читаю его при каждом запуске.
- **Резервная копия:** каждый день в 03:30 UTC (06:30 по Москве) в `/var/backups/projects/`, хранятся 14 последних. Сделать копию вручную: `systemctl start backup-projects`.
- **Как восстановиться из копии:**
  ```
  ls -lt /var/backups/projects/                          # выбрать архив
  mkdir /tmp/restore && tar -xzf /var/backups/projects/projects-ДАТА.tar.gz -C /tmp/restore
  ```
  Нужные файлы потом берёшь из `/tmp/restore/projects/`. Сначала распаковываем в отдельную папку, чтобы случайно не затереть текущие файлы. Можешь просто попросить меня: «восстанови файл X из копии за вчера».

**Три вещи, которые можно попросить прямо сейчас**
1. «Поставь Docker и подготовь шаблон проекта на Python с PostgreSQL в docker-compose, чтобы его было легко перенести в прод.»
2. «Подними ClickHouse и Grafana в Docker и сделай тестовый дашборд по данным GPS-трекеров.»
3. «Настрой Git и подключение к GitHub по SSH-ключу». Ключ я сгенерирую сам, а ты только добавишь его публичную часть в GitHub, без паролей в чат.

**Если я перестал отвечать**
1. Проверь интернет. Потом в VS Code: `Ctrl+Shift+P` → **Developer: Reload Window**, или переподключись к серверу.
2. Если не помогло, открой новый чат с Claude. Всё важное о тебе он узнает из `CLAUDE.md`.
3. Для длинных задач, которые должны идти без тебя, запускай меня в терминале внутри `tmux`: команда `tmux new -s claude`, затем `claude`. Если связь оборвётся, работа продолжится. Вернуться к ней: `ssh` на сервер и `tmux attach -t claude`.
4. Если не получается зайти даже по SSH, открой «консоль» (VNC) в личном кабинете хостинга. Через неё можно попасть на сервер в обход SSH и firewall.
